## Rules learned — two new, three confirmed

Numbering continues from R1–R5 in the 27/08 entry.

**R6. Absolute positioning with no positioned ancestor measures against the
viewport, not the page.**
An element with `position: absolute` inside a parent that is `static` resolves
its offsets against the initial containing block. The symptom is an element that
looks right at one viewport width and drifts linearly as the window changes.
Give the intended parent `position: relative` — do not compensate with
percentages.

**R7. When a layout misbehaves, check the DOM's element count and nesting BEFORE
reading CSS.**
`mega__in`'s parent reported `offsetWidth: 0`. No stylesheet explained it: a
missing `</a>` had swallowed the panel into the nav link, so the panel was a
descendant of an inline element. One console line — count the children of the
container and log their tag names — found it faster than three rounds of
stylesheet archaeology. Zero width with no width rule responsible is almost
always a nesting fault, not a cascade fault.

**Confirmed again tonight:** R1 (read live's source, not a screenshot), R3
(media queries last), R4 (core cannot override a section).

## Bugs fixed

Twenty-plus CSS and layout faults through the evening. The five worth recording:

1. The missing `</a>` above (R7). **Twice** — a slice operation consumed the
   closing tag on the first repair. Second fix applied and verified. When
   repairing markup by slicing, re-count the closing tags in the result.
2. Media-query block ordering in two guide sections (R3).
3. A `.wrap` shrink-to-fitting inside a grid parent (R2) — third occurrence.
4. Absolute-positioned caption drifting against the viewport (R6).
5. Footer monogram using the wrong asset.
